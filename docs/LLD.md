### 3.2 API Contracts

#### `POST /chat`
**Body:** `{ "question": "string" }`
**Returns:** `{ "response": "markdown string" }`

#### `POST /chat/stream`
**Body:** `{ "question": "string" }`
**Returns:** `text/plain` chunks streamed.

#### `POST /solve`
**Body:** `{ "question": "string" }`
**Returns:** `{ "solution": "markdown string" }`

#### `GET /quiz?count=5&subjects=A,B&chapters=X,Y&difficulty=easy&ai=true`
**Returns:** `{ "questions": [...] }`. Each question:
```json
{
  "id": 0,
  "ai_generated": true,
  "question": "...",
  "options": ["A","B","C","D"],
  "correct": 0,
  "explanation": "...",
  "subject": "Quantitative Aptitude",
  "topic": "Quantitative Aptitude",
  "chapter": "Percentage",
  "difficulty": "easy"
}
```

#### `GET /quiz/stream?...` (SSE)
Yields `data: <question_json>\n` per question, terminates with `event: done`.

#### `POST /quiz/submit`
**Body:** `{ "answers": [{question_index, selected_option, correct_option}], "topic": "..." }`
**Returns:** `{ "score": int, "total": int, ... }`

#### `POST /lessons`
**Body:** `{ "subject": "...", "chapter": "...", "difficulty": "medium", "exam": "..." }`
**Returns:** `{ "subject", "chapter", "difficulty", "exam", "content": "markdown" }`

#### `POST /lessons/stream`
Streams markdown tokens.

#### `GET /current-affairs?count=5&refresh=false`
**Returns:**
```json
{
  "items": [
    {"headline":"...","summary":"...","exam_angle":"...","category":"Polity","source_url":"https://..."}
  ],
  "generated_at": "ISO timestamp",
  "cached": true|false
}
```

### 3.3 Firestore Schema

| Path | Doc Fields |
| ---- | ---------- |
| `users/{uid}` | `name, email, photo_url, exam, goals[], created_at, onboarding_complete` |
| `users/{uid}/quiz_results/{auto}` | `score, total, pct, topic, difficulty, timestamp, questions[]` (each question carries `is_correct`, `user_answer`, `subject`, `chapter`, `difficulty`) |
| `users/{uid}/ai_notes/{auto}` | `title, content, source, subject, created_at, updated_at?` |
| `users/{uid}/viewed_lessons/{key}` | `subject, chapter, difficulty, last_viewed, view_count` |
| `users/{uid}/daily_lessons/{YYYY-MM-DD}` | `subject, chapter, difficulty, content, date, created_at` |
| `lessons/{subject__chapter__difficulty}` | `subject, chapter, difficulty, exam, content, created_at` |
| `current_affairs/{YYYY-MM-DD}` | `date, items[], generated_at` |

### 3.4 Firestore Security Rules (recommended)

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

      allow read: if request.auth != null;
      allow write: if request.auth != null;
    }
    match /current_affairs/{date} {
      allow read: if request.auth != null;

    }
  }
}
```

## 4. Adaptive Quiz Algorithm

```python
# Pseudocode used by Quiz Screen → "Smart Practice"
def pick_difficulty(avg_score):
    if avg_score >= 75: return "hard"
    if avg_score >= 50: return "medium"
    return "easy"

def pick_subjects(weak_topics):
    return [t['topic'] for t in weak_topics[:3]]

def start_adaptive(insights):
    if insights.total_quizzes == 0:
        # cold start: mixed easy 5-Q warm-up
        return QuizPlay(mode=mixed, count=5, difficulty=None)
    return QuizPlay(
        mode=custom,
        subjects=pick_subjects(insights.weak_topics),
        count=5,
        difficulty=pick_difficulty(insights.avg_score),
    )
```

Per-question outcomes (`is_correct`, `subject`, `chapter`, `difficulty`) feed back into next-cycle `getInsights` → `subject_breakdown` + `difficulty_breakdown` + `chapter_breakdown`.

## 5. RAG Context Composition (Chat)

`_buildContextualPrompt(userQuestion)` produces:

```
[STUDENT CONTEXT — use this to personalise your answer]
Student preparing for: <exam label>.
Study goals: <goal1>, <goal2>, ...
Performance: N quizzes, avg X%, pass rate Y%, Z-day streak.
Weak topics: ...
Strong topics: ...
Subject avgs (weakest first): SubjectA (45%), SubjectB (52%), ...
By difficulty: easy 82%, medium 64%, hard 41%.

[USER NOTES — they have saved these]
NOTE "title" [AI Tutor]: full content (if relevance score >= 3)
NOTE "title" [Manual]: excerpt (...) (if not directly relevant)
...
[END NOTES]

[RECENT LESSONS THE USER STUDIED]
- Subject / Chapter (difficulty, viewed Nx)
[END LESSONS]

[TODAY'S TOP CURRENT AFFAIRS]   ← only when ql contains "news"/"today"/etc.
• headline — summary [category]
[END CURRENT AFFAIRS]

[END CONTEXT]

<user's actual question>
```

Relevance scoring for notes:
- +3 per keyword match in title
- +1 per keyword match in content
- +1 if user message contains note-related keywords
- threshold 3 → include full content, else 150-char excerpt; cap 8 notes total

## 6. Streaming Protocol Details

### 6.1 Chat / Lesson Streaming (plain text)
Server returns `text/plain` with raw model chunks. Client just concatenates as they arrive.

### 6.2 Quiz Streaming (SSE)
Server emits `data: <single question JSON>\n\n` per validated question, then `event: done\n`. Client parses each `data:` line, JSON-decodes, yields a `Map<String, dynamic>`.

### 6.3 Error handling
- HTTP 500 from Ollama propagates as `"Ollama error: <code>"` in the body.
- Client catches via `try/catch`, displays SnackBar / inline error widget.
